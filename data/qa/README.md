# QA-корпуса в этом дереве

Здесь два файла — **собственные синтетические** данные команды, не данные организаторов и не результаты скрытой оценки:

| Файл | Что это | Почему лежит в репозитории |
|---|---|---|
| `regression_corpus_v1.json` (107 записей) | регрессионный корпус: тесты `tests/qa` читают его как фикстуру | без него suite не воспроизводится; в самом файле поля `kind` и `note` явно говорят, что это не оценочный набор |
| `acceptance_scenarios.json` | описание сценариев приёмки (намерения, не ответы) | документация приёмки |

**Загрязнение**: этот корпус использовался при подборе правил парсера, поэтому метрики на нём показывают переобучение (105/107 полных совпадений) и в отчёт как качество не идут — см. `docs/ACCURACY.md`.

**Настоящая закрытая выборка** (`holdout_v3`, ручная разметка до прогона парсера) **не лежит ни в репозитории, ни в образе**: она хранится вне дерева кандидата, а в Docker она не попадает (`.dockerignore`: `data/qa/`). Результаты прогонов (`data/qa/results/`) также вынесены из репозитория.

Правило на будущее: файлы, содержащие эталонные ответы для оценки, в репозиторий и образ не добавлять; для тестов использовать только этот регрессионный корпус.
