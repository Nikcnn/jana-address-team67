# RC-3: контракт стабилизации

Источник delta: прямое поручение владельца JANA ADDRESS от 18.10.2026 «FINAL STABILIZATION & RELEASE READINESS», вариант A. Это решение команды, **не подтверждение организаторов**.

База: приложенные `CONTRACT_v1.0.md` и `CONTRACT_v1.1.md`. Все endpoint, envelopes, лимиты и типы сохраняются; при конфликте старого C7 с этим документом применяется следующая явная delta.

## C3 / C7 — три независимых результата

1. Валидная строка, которую парсер не распознал: успешный обычный 14-польный ответ с неизвестными компонентами `null`. `raw_address` не меняется. Это не системная ошибка.
2. Повреждённый элемент: ровно одна fallback-запись на исходном индексе; безопасные `id` (string/integer, не bool) и `raw_address` (UTF-8 string) сохраняются по v1.1. Иначе соответствующее поле `null`. Все 11 адресных компонентов `null`, `confidence: 0.0`. Только такие fallback считаются в `X-Jana-Invalid-Items`. Невалидный id при допустимой строке нормализуется в null id, строка разбирается по v1.1. Строка >3000 символов не разбирается, но эхо сохраняется; прежняя per-item политика не изменяется.
3. Неожиданное исключение парсера/геосправочника либо нарушение внутреннего результата: HTTP 500 `{"detail":{"code":"internal_error"}}`, без успешного partial response и без заголовка malformed-items. Старый catch-all → blank в `parse_batch` отменяется. HTTP boundary фиксирует событие `parse_system_failure` и счётчик error_count; не выводит payload, id или текст исключения. Повторять запрос после устранения причины, а не трактовать отказ как адрес с нулевой уверенностью.

Envelope/JSON/число записей/размер запроса: прежние 400/422/413. Имена 14 output-полей и response envelope не меняются. На успешном batch cardinality равна входной, порядок и дубликаты сохраняются. На системном отказе вместо массива возвращается серверная ошибка — это явное требование владельца, не нарушение правила успешного cardinality.

## Синтетические тестовые корпуса

`data/qa/regression_corpus_v1.json` и `data/synthetic_corpus_v1.json` — собственные синтетические регрессии/нагрузка, не organizer data, не независимая закрытая выборка и не answer lookup в runtime. Они используются только тестами/скриптами и исключены из Docker image. Это описание фактического состава, а не утверждение о прежнем «принятом исключении» N1. Закрытые holdout/приватные данные не входят в RC. Никакая метрика на синтетике не называется точностью hidden evaluation.

## Release identity

У исходного репозитория unborn `main`, Git HEAD отсутствует. Коммит запрещён до отдельного разрешения; Git SHA не выдумывается. Идентичность исходников фиксируется SHA256-манифестом, идентичность runtime — Docker image ID и сверкой каждого runtime-файла. Отчёты/скриншоты/результаты не включаются в source manifest, чтобы измерения не изменяли проверяемый код. Отдельный evidence manifest хэширует пакет доказательств.

Новый RC не публикуется через прежний публичный tunnel без разрешения. Старый tunnel остаётся на RC-2 и не является доказательством приёмки RC-3. Обязательные GLM/Haiku review засчитываются только на точную версию и разрешённый, доказанный runtime route; исчерпание квоты = BLOCKED, не PASS.
